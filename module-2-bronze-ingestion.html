Connect the Sources (Bronze)

The Bronze layer makes all three Sudsberry sources readable in Fabric without moving or copying data out of them. You'll mirror the Azure SQL assessment database and the Cosmos DB property profiles into OneLake, and create a OneLake shortcut to the ADLS Gen2 appeal files - all surfaced through a single BronzeLakehouse.

Learning Objectives

  • Mirror the Azure SQL assessment database (parcels, assessments, sales, and reference tables).
  • Mirror the Cosmos DB properties container (property profiles + nested inspections).
  • Create a BronzeLakehouse and a OneLake shortcut to the ADLS appeal path.
  • Validate that all three sources are readable in Fabric.
  • Record the actual Fabric item names - the Silver notebooks expose them as editable parameters.

Why Mirror + Shortcut?

Mirroring continuously replicates operational databases into OneLake as Delta with no ETL pipelines, and shortcuts expose file data in place with zero copy. Sudsberry keeps its systems of record where they are; Fabric reads them on OneLake. No source server or storage names are ever embedded in your notebooks.

Figure 2.1 - Two mirrors and one shortcut converge on a single Bronze Lakehouse.
⚠
Obtain connection details and credentials from your facilitator. Do not paste credentials into a notebook or commit them anywhere.

Part A - Mirror Azure SQL MIRROR

  1. Create a Mirrored Azure SQL Database

    In your workspace, click + New item → search "Mirrored" → Mirrored Azure SQL Database. Name it Property Assessment SQL Mirror and enter the connection details supplied for your lab (see Get Started).

  2. Select the assessment tables

    Choose the tables and begin mirroring. Confirm all eight appear:

    Jurisdiction, Neighborhood, PropertyClass, Parcel, Building, Assessment, Sale, TaxRate.

    ✓
    Computed columns: SQL mirroring may omit the computed AssessedValue. That's fine - you'll re-derive Land + Improvement value in Silver.

  3. Watch replication reach a steady state

    The mirror snapshots first, then switches to incremental change data capture. Wait for the tables to report Replicated.

Part B - Mirror Cosmos DB MIRROR

  1. Create a Mirrored Azure Cosmos DB item

    Click + New item → Mirrored Azure Cosmos DB. Name it Property Profiles Mirror and connect to the account provided by the facilitator.

  2. Select the properties container

    Choose the database and the properties container. Confirm that property-profile fields and the nested inspections data are visible.

    ⓘ
    Each document's id equals its parcelId and it is partitioned by /neighborhoodId - the same keys that join back to the SQL tables. You'll flatten the nested structure into property_profile and explode inspections[] into fact_inspection in Silver.

Part C - Create the ADLS Shortcut SHORTCUT

  1. Create the Bronze Lakehouse

    Click + New item → Lakehouse → name it BronzeLakehouse.

  2. Shortcut the appeal files

    Under Files, right-click → New shortcut → Azure Data Lake Storage Gen2. Connect to the supplied appeal-data path and name the shortcut appeals.

    Confirm both assessment_appeals.json and assessment_appeals.parquet are visible under Files/appeals/.

Validation

Prove all three sources are readable. Open the Bronze Lakehouse SQL analytics endpoint (or a notebook) and run quick checks:

T-SQL 
-- SQL mirror is queryable
SELECT TOP 5 ParcelId, NeighborhoodId, PropertyClassCode FROM Parcel;

-- Assessment values are present (AssessedValue re-derived later in Silver)
SELECT TOP 5 ParcelId, TaxYear, LandValue, ImprovementValue FROM Assessment;
PySpark 
# Read the Parquet appeals from the shortcut and count records
appeals = spark.read.parquet("Files/appeals/assessment_appeals.parquet")
print("appeal records:", appeals.count())
display(appeals.select("appealId", "parcelId", "reasonCode", "status").limit(5))
