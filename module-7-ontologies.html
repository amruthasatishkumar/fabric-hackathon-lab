Model a Fabric Ontology

Create a governed business vocabulary over the Gold marts before configuring the data agent. The ontology makes properties, neighbourhoods, sales, and appeals explicit business concepts and turns their shared keys into traversable relationships the agent can reason over.

⚠
Preview prerequisites. Fabric Ontology is a preview capability in the Fabric IQ workload. Your tenant admin must enable the Ontology item (preview) setting, and the Fabric data agent tenant settings must be enabled before the data agent step. Complete notebook 4 first so all four managed Gold Delta tables exist.

Learning Objectives

  • Create a PropertyAssessmentOntology item bound directly from OneLake Gold.
  • Define and bind four entity types (Property, Neighborhood, ComparableSale, Appeal).
  • Create four directional relationships across the shared keys.
  • Refresh and validate the graph so entity and relationship grounding works.

Step 1 - Create the Ontology ONTOLOGY

  1. Create the item from OneLake

    In the Fabric workspace, select New item → Ontology. Name it PropertyAssessmentOntology - ontology item names support letters, numbers, and underscores; no spaces or dashes.

    Choose to build directly from OneLake. Do not generate the ontology from the semantic model.

    ⓘ
    Direct OneLake binding is intentional. It exposes the entity keys, property bindings, and relationship mappings that an automatically generated model would hide from the exercise.

Step 2 - Create & Bind Entity Types

For each entity, select Bind data, browse to GoldLakehouse, choose the table in the dbo schema, map the listed properties, define the entity key, and set the display property. Keep the source columns unchanged.

Step 4 - Refresh & Validate the Graph

Refresh the graph model after saving all bindings - upstream Lakehouse changes aren't visible in the ontology until the graph is refreshed, then confirm each entity type is populated and its relationships traverse correctly.

ⓘ
If numeric values appear null, verify the source types in the binding. Ontology and Graph are preview features; keep authoritative decimal values in Gold and use a double-typed ontology projection only if the tenant can't bind a required decimal property.

Current Preview Constraints

  • Ontology must be enabled at the tenant level and requires Fabric capacity.
  • The Fabric data agent and its Copilot tenant settings must be enabled separately.
  • Bound Lakehouse tables must be managed tables, must not use OneLake security, and must not have Delta column mapping enabled.
  • Source changes require a graph refresh.
  • Ontology and agent behaviour can change while these features are in preview.

What You Just Built

A validated semantic graph over the Gold marts - four entities, four relationships, Property as the anchor. Next, a Fabric Data Agent is grounded on PropertyAssessmentOntology so questions become relationship traversals.
