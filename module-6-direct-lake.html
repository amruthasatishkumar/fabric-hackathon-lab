Direct Lake Semantic Model + Power BI

Build a Direct Lake star-schema semantic model over your curated tables and ship a property-assessment report. No import, no DirectQuery overhead - Power BI reads the Delta files in OneLake directly, with live data freshness.

Learning Objectives

  • Create a Direct Lake semantic model with a star schema.
  • Keep assessments, sales, inspections, and appeals as separate facts at their natural grains.
  • Author core property-assessment DAX measures.
  • Auto-create and polish a report; verify Direct Lake storage mode.

Build the Semantic Model DIRECT LAKE

ⓘ
What is Direct Lake? A Power BI storage mode that reads Delta files in OneLake directly - import-mode performance with live freshness. The semantic model is just metadata pointing at your Lakehouse tables.

  1. Create the semantic model

    From SilverLakehouse, click New semantic model. Pick the star-schema tables:

    • Dimensions: dim_parcel, dim_neighborhood, dim_property_class (add a Date dimension if available)
    • Facts: fact_assessment, fact_sale, fact_inspection, fact_appeal_ai

    Name it Property Assessment Model. Click Confirm.

  2. Define relationships

    Open the model → Model view and draw:

    Relationships 
    fact_assessment[parcel_id]  ──*──1── dim_parcel[parcel_id]
fact_sale[parcel_id]        ──*──1── dim_parcel[parcel_id]
fact_inspection[parcel_id]  ──*──1── dim_parcel[parcel_id]
fact_appeal_ai[parcel_id]   ──*──1── dim_parcel[parcel_id]
dim_parcel[neighborhood_id] ──*──1── dim_neighborhood[neighborhood_id]
dim_parcel[property_class_code] ──*──1── dim_property_class[property_class_code]

  3. Add core measures

    Right-click fact_assessment → New measure. Add the property-assessment measures:

    DAX 
    Total Assessed Value = SUM(fact_assessment[assessed_value])

Average Assessed Value = AVERAGE(fact_assessment[assessed_value])

Assessment to Sale Ratio =
    DIVIDE(
        AVERAGE(fact_assessment[assessed_value]),
        AVERAGE(fact_sale[sale_price]),
        BLANK()
    )

Appeal Count = DISTINCTCOUNT(fact_appeal_ai[appeal_id])

Negative Sentiment Rate =
    DIVIDE(
        CALCULATE([Appeal Count], fact_appeal_ai[ai_sentiment] = "negative"),
        [Appeal Count],
        0
    )
    ✨
    Other useful measures from the repo: year-over-year valuation change, estimated tax, appeal rate, median requested adjustment, resolution rate, average resolution days, and AI enrichment success rate.

  4. Create and polish the report

    Top of the model → Create report → Auto-create, then refine. Report ideas from the repo:

    1. Assessment overview: values, taxes, classes, and neighbourhood trends.
    2. Comparable sales: assessment-to-sale distributions and outliers.
    3. Appeal operations: volume, status, reasons, resolution time, and outcomes.
    4. Appeal intelligence: sentiment, summaries, themes, and follow-up signals.
    5. Property detail: parcel, building, assessment, sale, inspection, and appeal history.

    Save as Property Assessment Insights.

    ✨
    Let Copilot build it. In the report canvas, click Copilot and ask, e.g., "Create a page showing average assessed value by neighbourhood and appeal count by reason." The Direct Lake model gives it the schema and measures to ground responses.

  5. Validate Direct Lake mode

    In the model settings, each table's Storage mode should read Direct Lake. If it shows DirectQuery, the capacity may not support Direct Lake - contact lab support.
